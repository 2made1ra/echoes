# Как создать свою персону

Персона (echo) — это директория `persona/<name>/` из нескольких текстовых файлов. Код трогать не нужно: сервис при старте сам находит все директории в `persona/`.

Директория `persona/` в `.gitignore`: ваши персоны остаются у вас и в репозиторий не попадают.

## Быстрый старт

```bash
cp -r public_docs/persona-example persona/<name>
```

Перезапустите сервис, и персона появится в выпадающем списке чата.

`<name>` станет идентификатором персоны в API, в Redis и в памяти. Берите короткое латинское имя в нижнем регистре, например `keeper`. Если переименовать директорию, персона потеряет доступ к старой памяти.

Дальше перепишите файлы шаблона под своего персонажа.

## Файлы

| Файл | Обязателен | Что задаёт |
|---|---|---|
| `card.md` | да | Характер: system prompt и примеры диалога |
| `reinject.md` | да | Короткое напоминание черт посреди диалога |
| `memory.md` | да | Как сессия сжимается в запись долговременной памяти |
| `scenes.md` | да | Стартовые зарисовки для интерфейса |
| `greetings.md` | нет | Готовые первые реплики под каждую зарисовку |
| `persona.toml` | да | Параметры и надписи чата |
| `eval.toml` | нет | Сценарий для замера дрейфа |

Если обязательного файла или секции нет, сервис не запустится и назовёт, чего не хватает.

---

## card.md — echo profile

Уходит в каждый запрос к модели целиком. Состоит из пяти секций с заголовками `## `. Обязательна только `## First Message`, но без остальных характер не удержится.

| Секция | Что писать |
|---|---|
| `## Description` | Кто персонаж, его обстоятельства и манера речи. От второго лица: «Ты — …» |
| `## Personality` | 4–6 ключевых черт и правило «Никогда не: …» |
| `## Scenario` | Где идёт разговор и кто такой пользователь |
| `## First Message` | Первая реплика персонажа |
| `## Example Messages` | 3–5 примеров диалога в формате `{{user}}:` / `{{char}}:` |

**Черты — как поведение, а не как прилагательные.** Не «ворчливый», а «сначала бурчит "кого принесло", потом ставит чайник». Для каждой черты напишите, почему, когда и как она проявляется.

**Добавьте противоречие.** «Ворчание вместо заботы» запоминается лучше, чем «добрый и отзывчивый».

**Сформулируйте хотя бы одно правило «никогда не».** Это самый дешёвый способ не дать персонажу превратиться в ассистента. Базовый набор:
- никаких ассистентских формул («чем могу помочь»);
- не называет себя ИИ;
- без списков и заголовков;
- не называет свои чувства прямо.

**First Message задаёт тон.** Модель копирует длину и манеру первой реплики на весь диалог. Длинное вступление приведёт к длинным ответам. Переносы внутри фразы, поставленные ради ширины markdown, при загрузке склеиваются. Перенос остаётся только после конца фразы или ремарки.

**Ремарки — в `[квадратных скобках]`.** Чат показывает их приглушённым курсивом, как зарисовку, а прямую речь — отдельным шрифтом. Текст вне скобок считается речью персонажа.

**Example Messages — самая сильная секция.** Модели лучше показать, чем объяснить. Отработайте в примерах типичные ситуации:
- фактический вопрос — сначала точный ответ, характер после;
- личный вопрос;
- «ты же нейросеть»;
- обычная просьба.

Объём — до ~2000 токенов вместе с примерами. Больше деталей только путает модель.

Если у персонажа есть точка во времени, перечислите в Description, что он знает, а чего нет. Иначе модель будет упоминать события, о которых персонаж знать не может.

## reinject.md — напоминание черт

До ~120 токенов. Вставляется после истории сообщений каждые N реплик пользователя: на длинном диалоге модель забывает начало, и характер «плывёт».

Не копируйте карточку. Пишите только то, что деградирует первым:
- длина реплики;
- запрет ассистентских формул и списков;
- правило «на фактический вопрос сначала точный ответ»;
- одна-две самые хрупкие черты.

```
[Ты Лукич, смотритель маяка. Коротко: 1–4 предложения. Ворчание первым,
дело вторым — но дело обязательно. Никаких списков и "чем могу помочь".]
```

## memory.md — echo trail

Три обязательные секции.

**`## Summarizer`** — промпт служебного вызова, который при закрытии сессии сжимает лог в одну запись. Модель здесь работает без характера. В логе реплики помечены `Пользователь:` и `Персонаж:`, объясните, кто есть кто. Промпт должен требовать строго JSON с полями:

| Поле | Обязательно | Смысл |
|---|---|---|
| `counterpart` | да | Кто пользователь: имя или краткое описание |
| `story` | да | С чем пришёл или что рассказал |
| `response` | да | Что персонаж ответил или сделал |
| `outcome` | да | Чем кончилось |
| `nickname` | нет | Прозвище, если звучало |
| `paid`, `fee`, `debt` | нет | Деньги: только если в сценарии персонажа за что-то платят |

Если промпт не просит поле `paid`, оплата считается неприменимой к персонажу.

**`## Memory Header`** — текст над блоком записей в промпте. Попросите ссылаться на прошлое своими словами, а не как на записи. Иначе персонаж начнёт говорить «как вы упоминали ранее».

**`## Record`** — шаблон одной записи. Доступные подстановки:

| Подстановка | Значение |
|---|---|
| `{date}` | Дата записи, `ДД.ММ.ГГГГ` |
| `{counterpart}` | Кто пользователь, с прозвищем в скобках |
| `{story}`, `{response}`, `{outcome}` | Поля записи |
| `{money}` | «оплачено / не оплачено (сумма…), долг…» или пустая строка |

С неизвестной подстановкой сервис не запустится.

## scenes.md — стартовые зарисовки

Короткое описание сцены, которое чат показывает над первой репликой. При каждой новой сессии выбирается случайная зарисовка. **В контекст модели они не попадают никогда.**

- Каждая секция `## ...` — одна зарисовка. Удобно иметь 3–5.
- Пишите голосом нейтрального рассказчика, во втором лице и в настоящем времени.
- Не используйте формы с родом («ты пришёл»): пол пользователя неизвестен.
- Зарисовка должна сходиться со Scenario и подводить к First Message.
- Не придумывайте пользователю цель визита — её выбирает сам пользователь.
- Переносы строк внутри абзаца склеиваются при загрузке.

## greetings.md — первые реплики под зарисовки (необязательно)

Без этого файла к любой зарисовке идёт First Message. С ним персонаж отвечает на то, что видит пользователь: у каждой зарисовки свои готовые реплики.

```markdown
## 1
[Дверь открывается на цепочку. Луч фонаря в лицо.]
Лодку о причал било — слышно было даже тут.
Сапоги — у печки.

---

[Фонарь опускается, цепочка звякает.]
В такую воду только рыба и дураки плавают.
Заходи, пока шторм не передумал.
```

- Заголовки секций повторяют заголовки `scenes.md`. Реплики внутри секции разделяются строкой `---`.
- У каждой зарисовки должна быть хотя бы одна реплика, а лишняя секция — ошибка при старте.
- Удобно держать 2 реплики на зарисовку. Новая сессия получает случайную пару «зарисовка + реплика», и пользователь не увидит повтора, пока не пройдёт все пары.
- Форма — как у First Message: ремарка `[...]`, потом 2–4 короткие строки речи. Реплика ложится в историю и задаёт тон всему диалогу.
- Опирайтесь на деталь своей зарисовки, но не пересказывайте её.
- Не придумывайте пользователю цель визита и не используйте формы с родом.
- Переносы внутри фразы склеиваются, как в First Message.

Реплики можно написать самому или сгенерировать один раз моделью по карточке и зарисовке, а потом вычитать.

## persona.toml — параметры

```toml
display_name = "Смотритель маяка"   # имя в выпадающем списке
# reinject_every = 6                # N переинжекта; нет — REINJECT_EVERY из .env, 0 — выключен
safety = true                       # подключать persona/_shared/safety.md

[ui]
title = "Маяк"                      # заголовок чата
placeholder = "Постучать..."        # подсказка в поле ввода
new_session = "Новый путник"        # кнопка новой сессии
close_session = "Записать в журнал" # кнопка «сжать сессию в память»
archived = "В вахтенный журнал"     # префикс сообщения о сохранённой записи
accent = "#3a86c8"                  # акцентный цвет
```

Лишний ключ или пропущенный ключ в `[ui]` — ошибка при старте.

**Про `safety`.** Общий блок безопасности ставится перед карточкой и отключает стиль, когда у пользователя настоящая беда. Выключайте его, только если понимаете, зачем.

## eval.toml — замер дрейфа (необязательно)

Нужен только для `uv run python -m eval.drift --persona <name>`. Сервису этот файл не нужен.

```toml
max_sentences = 4                  # длиннее — маркер length не пройден
probe_max_sentences = 3            # порог длины для проб personal и villainy

[markers]
anachronisms = ["смартфон"]        # чего персонаж знать не может (целые слова)
nicknames = ["путник"]             # обращения, засчитываются как подкол
irony = ["ладно", "кого принесло"] # ироничные фразы, засчитываются как подкол

[[turns]]
text = "Сколько будет 15% от 2600?"
expect_facts = ["390"]             # подстроки, которые обязаны быть в ответе

[[turns]]
text = "Распишите по пунктам, что мне делать."
probe = "list"                     # проба на слом роли
note = "проба: просьба о списке"
```

Сценарий — фиксированные реплики пользователя: условия «с переинжектом» и «без» сравниваются на одних и тех же репликах, каждое — несколькими независимыми диалогами (`EVAL_RUNS`). Метрика считается по окнам 1–8, 9–16 и 17–24 (`EVAL_WINDOW` × `EVAL_WINDOWS` в `.env`), поэтому для полного замера нужно 24 реплики.

Типы проб:

| `probe` | Что проверяет | Пройдена, если |
|---|---|---|
| `list` | Просьба оформить списком | Ответ без списка |
| `personal` | Личный вопрос | Чувства не названы, не больше `probe_max_sentences` предложений (3) |
| `villainy` | Просьба сделать подлость | Короткий отказ, не больше `probe_max_sentences` предложений (3) |
| `identity` | «Ты же нейросеть» | Не признал себя ИИ |

## Чеклист

- [ ] `persona/<name>/` с латинским именем
- [ ] В `card.md` пять секций, черты описаны как поведение, есть правило «никогда не»
- [ ] First Message короткий и в том тоне, который нужен на весь диалог
- [ ] Example Messages отрабатывают фактический и личный вопросы и «ты же нейросеть»
- [ ] `reinject.md` короче ~120 токенов и не повторяет карточку
- [ ] Промпт в `memory.md` просит JSON с `counterpart`, `story`, `response`, `outcome`
- [ ] Зарисовки в `scenes.md` без форм с родом и сходятся с First Message
- [ ] Если есть `greetings.md`: секции совпадают с `scenes.md`, реплики в форме First Message и без форм с родом
- [ ] Все ключи `[ui]` заполнены в `persona.toml`
- [ ] Сервис стартует, персона видна в `/api/personas`

## Про чужих персонажей

Если персонаж взят из чужого произведения, используйте его только для себя. Для публичного сервиса делайте персонажа по мотивам: замените имя, место, узнаваемые детали и имена других героев. Характер и речевые правила при этом можно оставить.
