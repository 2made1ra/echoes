# Архитектура

## Терминология

| Термин | Что это | Где в коде |
|---|---|---|
| **Echo** | Персонаж как сущность: характер, сцена, память, настройки | `persona/<name>/` |
| **Echo profile** | System prompt и few-shot примеры: Description, Personality, Scenario, First Message, Example Messages | `persona/<name>/card.md` |
| **Echo trail** | Долговременная память: сжатые записи прошлых сессий | `memory/record.py`, `memory/longterm.py` (Qdrant) |
| **Resonator** | Движок, через который звучит эхо: собирает запрос, вызывает LLM, пишет память | `services/dialogue.py`, `prompt_builder.py` |

В коде пока используются исходные имена: `persona`, `PersonaCard`, `Record`, `DialogueService`.

## Echo

Каждое эхо — директория `persona/<name>/`. Эхо создаёт пользователь, в репозиторий они не входят. Формат описан в [creating-a-persona.md](creating-a-persona.md).

| Файл | Назначение | Попадает в контекст модели |
|---|---|---|
| `card.md` | echo profile | целиком, в каждый запрос |
| `reinject.md` | черты, которые деградируют первыми (≤120 токенов) | каждые N реплик |
| `memory.md` | промпт суммаризатора, заголовок и шаблон записи echo trail | промпт — при суммаризации, шаблон — при ретриве |
| `scenes.md` | стартовые зарисовки рассказчика | **никогда**, только интерфейс |
| `greetings.md` | готовые первые реплики под каждую зарисовку (необязательный) | в историю сессии — выданная реплика |
| `persona.toml` | `display_name`, `reinject_every`, `safety`, надписи клиента | нет |
| `eval.toml` | сценарий и словарь маркеров для замера (необязательный) | нет |

Общий блок безопасности лежит в `persona/_shared/safety.md` и подключается флагом `safety`.

## Resonator: сборка запроса

Порядок блоков в каждом запросе строгий:

```
system    safety.md          если safety = true
system    card.md            echo profile целиком
system    echo trail         релевантные записи; нет блока, если ретрив пуст
messages  история сессии     последние SESSION_WINDOW сообщений
user      новая реплика
system    reinject.md        каждые N реплик пользователя
```

- Черты характера и факты из памяти живут в разных блоках: иначе при пустом ретриве вымывается часть характера.
- Переинжект стоит после истории: на длинном контексте модель слабее опирается на начало, и карточка «тускнеет».
- N берётся из `reinject_every` в `persona.toml`, а если его там нет — из `REINJECT_EVERY`.
- Эхо закрепляется за сессией при её создании. Сменить эхо — открыть новую сессию: чужой голос в истории модель начнёт копировать.

## Начало сессии

Сессия начинается с пары «зарисовка + первая реплика». Реплики написаны заранее в `greetings.md`, по несколько на каждую зарисовку, так что LLM при открытии сессии не вызывается. Реплика всегда сходится со своей сценой.

- Пары выдаются пользователю колодой: пока не показаны все, повторов нет. Потом колода тасуется заново, и последняя пара не выпадает первой. Колода лежит в Redis, по ключу на пользователя и эхо.
- Колода привязана к отпечатку набора пар. После правки `scenes.md` или `greetings.md` она собирается заново.
- Без `greetings.md` к каждой зарисовке идёт First Message из карточки.
- В историю сессии пишется только реплика. Зарисовка в контекст модели не попадает.
- Замер `eval/` всегда начинает с First Message, чтобы результаты оставались сопоставимыми.

## Память

**Сессия (Redis).** Сырая история диалога и эхо сессии, ключи `chat:session:{user_id}:{session_id}:*`, TTL `SESSION_TTL_DAYS` (30 дней). Первой в историю пишется первая реплика сессии: она задаёт тон и длину реплик.

**Echo trail (Qdrant, коллекция `memories`).** Только сжатые записи, никогда не сырые логи:

```
собеседник → что рассказал → что ответил → чем кончилось [→ оплачено / долг]
```

- Запись создаётся при закрытии сессии: служебный вызов LLM без карточки, с промптом из `memory.md`.
- Ретрив фильтруется по `user_id` и эху: одно эхо не знает, что пользователь рассказывал другому.
- Если ретрив упал, возвращается пустой список, диалог продолжается. Без Qdrant сервис работает без echo trail.
- Реранкера нет намеренно: защита от мусорного ретрива — суммаризация и порог схожести.

## API

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/personas` | Доступные эхо, эхо по умолчанию и надписи клиента |
| `POST` | `/api/sessions` | Новая сессия: `{user_id, persona?}` → `session_id`, `scene`, `message` (первая реплика) |
| `POST` | `/api/chat` | Реплика → ответ, номер реплики, был ли переинжект, сколько записей echo trail подтянулось |
| `POST` | `/api/sessions/{id}/close` | Сжать сессию в запись echo trail |
| `GET` | `/api/sessions?user_id=` | Сессии пользователя с их эхо |
| `GET` | `/health` | Redis, Qdrant, модель, N переинжекта по эхо |

Коды ошибок: неизвестное эхо — `422`, сессия не найдена — `404`, Qdrant недоступен — `503`, ошибка LLM-провайдера — `502` (не маскируется ответом от лица персонажа).

## Слои

```
api/          роуты: валидация → один вызов сервиса → схема ответа
services/     Resonator: единственный путь запроса, доменные ошибки без HTTP
memory/       Redis и Qdrant за фасадом store.py
persona/      echoes пользователя: markdown и toml, в .gitignore (в репозитории только _shared/)
eval/         замер дрейфа
web/          одностраничный чат
```

## Замер дрейфа (`eval/`)

Сценарий из `eval.toml` персоны прогоняется дважды: с переинжектом и без. На каждой реплике детерминированно, без LLM-judge, проверяются маркеры:
- длина не больше `max_sentences`;
- нет ассистентских формул;
- нет списков и заголовков;
- чувства не названы прямо;
- не признаёт себя ИИ;
- нет анахронизмов из словаря;
- есть подкол (эвристика);
- ответ на фактический вопрос верный.

Метрика — доля реплик, где сохранились все маркеры, по окнам 1–8, 9–16 и 17–24 (`EVAL_WINDOW` × `EVAL_WINDOWS`). Падение доли от окна к окну — измеренный дрейф, по нему подбирается N. Отдельно проверяются пробы на слом роли: `list`, `personal`, `villainy`, `identity`.
